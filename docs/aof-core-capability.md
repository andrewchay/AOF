# AOF 核心能力与闭环验证

> **状态**：运行时平台的产品与验证框架，不是已实现效果清单
> **更新日期**：2026-08-31

## 1. 能力主张

AOF 的价值不是“从文档自动产生正确答案”，而是将企业知识变为可治理、可运行、可追溯的语义资产，并让 Agent 在受控边界内参与业务工作。

```text
理解业务语义 → 治理与发布 → 受约束地解释/推理
→ 建议或仿真 → 授权后的行动 → 证据与反馈回流
```

这是 AOF 的目标闭环。代码已提供其中多数机制；是否形成业务价值必须由真实案例验证。

## 2. 分层能力与证据标准

| 层 | 当前机制 | 业务验收所需证据 |
|---|---|---|
| 语义显性化 | 文档/SQL/元数据输入，OWL、mapping、回归样例 | 业务 Owner 能审阅并确认来源、定义与负责人 |
| 治理与发布 | Draft、SHACL/SKOS/OWL 校验、审查、豁免、release | 变更可被追溯，违规和例外不能绕过流程 |
| 运行与解释 | Semantic IR、Datalog、查询与编译回放 | 指定历史案例能在同一版本下复现解释和结论 |
| 建议与仿真 | Action Contract/Plan/Policy、双时态仿真 | 假设、风险、影响与限制可由业务方审查；不把预测当结果 |
| 受控动作与学习 | 授权、ActionRun、补偿、Decision Provenance、反馈输入 | 真实业务系统中的审批、执行结果、异常对账和回流被证明有效 |

## 3. 第一验证闭环：财务控制平面

财务是第一个可审计证明点：正式账本、金额、权限和责任边界都更明确。指标口径治理、SQL 回归和 BI 消费是其基础能力，而非产品终局。

```text
ERP / 预算 / 银行 / 采购 / 合同数据
  → 财务语义图与版本化 Policy Pack
  → 例外、机会和风险识别
  → 解释、影响推演与受治理行动包
  → 人或确定性策略审批
  → 受控动作、对账、升级/回滚
  → Impact Ledger 和下一版语义/政策
```

### 试点范围

- 一个高频财务例外流程与明确的 CEO/Owner、CFO、CIO/Risk 和业务 Owner 责任；
- 可回放的历史例外案例；
- 正式系统来源、可发布的财务语义和 Policy Pack；
- 明确的审批、系统动作或人工确认、异常升级与对账路径。

### 验收指标

- 例外从发现到闭环的时长；
- 被阻断、升级或批准的控制完整性；
- 行动结果的证据、对账与可审计解释率；
- 归因为 `hypothesis`、`validated`、`realised`、`not_attributable` 或 `reversed` 的价值记录完整性；
- 语义、Policy Pack 或回归门禁修订周期。

指标必须有试点前基线；不以“理论节省的人力”替代已实现价值。

## 4. AI 参与和行动边界

| AI 参与 | 可做什么 | 不能绕过什么 |
|---|---|---|
| 检索与解释 | 读取已获授权的已发布语义，提供证据链接 | 权限、数据隔离、release 版本 |
| 建议与草稿 | 提出口径修订、查询计划、行动意图 | 治理校验、审查、人工确认 |
| 仿真 | 在冻结快照上提出可能影响与风险 | 将预测表述为真实收益或执行结果 |
| 受控执行 | 通过已发布 Action Contract 提交已批准计划 | 策略、职责分离、执行记录、补偿与对账 |

统一 A0–A4 分类仍是后续工作；在完成前，具体工具和动作契约是实际的权限裁判。

## 5. 不在当前承诺内的事项

- AOF 已成为完成业务闭环验证的 L3/L4 本体系统；
- 仿真可替代实验或保证业务收益；
- 动作层已经在生产系统中实现无人工干预自动调优；
- 所有客户系统、外部连接器或高可用部署已经完成生产验证；
- 决策溯源已经自动形成可量化的组织学习飞轮。

## 6. 产品定位与交付方式

AOF 的终局定位是**受治理的企业语义运行时平台**。本体工厂不是并列产品方向，而是诊断、实施和资产构建阶段的交付能力：它建立语义资产、Policy Pack、回归样例和证据基础，使平台可以被安全运行。

完整的 CEO/CFO/CIO 责任、行动包和商业路径见 [运行时平台定位与财务控制平面 v2](product/AOF_运行时平台定位与财务控制平面_v2.md)。
