
# AOF 数字化孪生核心能力体系

> 版本: v1.0  
> 创建时间: 2026-04-01  
> 适用场景: 老业务数字化升级，基于已有文档构建可计算的业务本体

---

## 概述

AOF（AI Ontology Framework）为老业务带来的核心价值是：**无需大规模基建改造，即可基于现有文档和数据构建可计算的业务数字孪生**。

本体系包含5大核心能力，形成"理解→生成→推演→执行→进化"的完整闭环。

---

## 五项核心能力总览

| 层级 | 能力名称 | 核心定位 | 关键动作 |
|:---:|---------|---------|---------|
| **认知层** | 1. 业务知识显性化 | 从文档中重建业务本体 | 提取实体/关系/规则，形成可计算的业务模型 |
| **认知层** | 2. 即时迭代 | 本体持续进化 | 专家打标→回喂→本体更新，渐进式完善 |
| **策略层** | 3. 策略自动生成 | 基于业务状态，AI推荐策略 | 诊断结果→匹配策略库→生成可执行方案 |
| **策略层** | 4. 策略仿真推演 | 预演策略效果，评估风险 | 虚拟执行→预测指标变化→避免盲目上线 |
| **策略层** | 5. 策略执行与监控 | 将策略落地为具体动作 | 生成指令→调度系统→实时监控→自动调优 |

## 能力一：业务知识显性化

> 原则：**从底向上建立，使用过程中逐步完善，避免大量基建和标注**

### 核心定义
即使老业务没有非常好的数据基建，AOF也能基于已有文档（业务规范、数据口径、历史分析报告）自动构建业务本体和属性关系，让业务知识可被AI理解、可计算。

### 关键特性

| 特性 | 说明 | 对比传统方式 |
|-----|------|-------------|
| **文档即本体** | 从非结构化文档（PDF/Word/KM）自动提取实体、关系、规则 | 传统：人工阅读→手动建模→数月交付 |
| **渐进式构建** | 不追求完美，先有框架再用中完善 | 传统：追求大而全，迟迟无法上线 |
| **计算就绪** | 提取的知识直接映射到可执行查询（SPARQL/SQL） | 传统：知识库与数据层割裂 |

### 技术实现示例

```turtle
# 从"网充业务周报规范"文档自动提取
:InhouseTopupActivity a owl:Class ;
    rdfs:label "网充活动" ;
    :definedInDocument <https://km.mihoyo.com/doc/mhy5x9ry0q3i> ;
    :hasAttribute [
        :attributeName "有效渗透率" ;
        :calculation "is_valid_view_h5 / user_num" ;
        :dataSource "biz_growth.hk4e_63_topup_user_analysis_di"
    ] ;
    :hasAttributionChain :GlobalAttributionChain .

:GlobalAttributionChain a owl:Class ;
    :hasSteps (
        :Step1_TargetUsers 
        :Step2_QSelected 
        :Step3_Reachable
        :Step4_ActuallyExposed
        :Step5_ValidlyExposed
        :Step6_MarketingLeakage
        :Step7_TotalValidLeakage
    ) .
```

### 业务价值
- **零基建启动**：不需要先清洗数据、建数据仓库，从文档开始即可
- **知识可传承**：业务专家的隐性经验变成显性的、可查询的本体定义
- **AI可理解**：LLM不再"幻觉"，基于结构化本体进行推理

## 能力二：即时迭代

> 原则：**在使用过程中持续优化，专家反馈即时回喂**

### 核心定义
基于新的业务文档、以及使用过程中的对话内容，邀请业务专家对AI的理解进行打标和纠正，再将反馈回喂给本体，形成"使用→反馈→优化→更好用"的正向循环。

### 迭代闭环流程

```
┌─────────────────────────────────────────────────────────┐
│                    即时迭代闭环                          │
├─────────────────────────────────────────────────────────┤
│                                                          │
│   [用户提问] "6.4下半纯新玩家的渗透率怎么算？"            │
│       │                                                  │
│       ▼                                                  │
│   [AI回答] 基于当前本体解释计算口径...                    │
│       │                                                  │
│       ▼                                                  │
│   [专家反馈] ❌ "不对，纯新玩家应该排除回流玩家"          │
│       │        （点击纠正，补充定义）                      │
│       ▼                                                  │
│   [打标记录] 记录：{query, wrong_answer, correct_rule}    │
│       │                                                  │
│       ▼                                                  │
│   [本体更新] 自动更新 :NewPlayer 定义                     │
│       rdfs:subClassOf :Player ;                          │
│       :excludes :ReturningPlayer .                       │
│       │                                                  │
│       ▼                                                  │
│   [验证测试] 用历史查询验证修正后的准确性                  │
│       │                                                  │
│       └──────────────────────┐                          │
│                                ▼                         │
│                    [下一轮对话，更准确的回答]              │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 迭代类型

| 类型 | 触发场景 | 处理方式 |
|-----|---------|---------|
| **概念纠正型** | AI对业务概念理解错误 | 专家直接编辑本体定义 |
| **口径更新型** | 业务口径变更（如新增过滤条件） | 版本化管理，保留历史口径 |
| **关系补充型** | 发现新的实体关联 | 动态添加ObjectProperty |
| **策略积累型** | 新策略执行后效果良好 | 将策略加入策略库本体 |

### 业务价值
- **越用越准**：不是一次性项目，系统随使用不断进化
- **专家知识沉淀**：业务专家的纠正自动变成系统能力
- **低成本维护**：不需要专职团队维护，在使用过程中自然完善

## 能力三：策略自动生成

> **从"看数据"到"知道该做什么"**

### 核心定义
基于业务诊断结果（如归因断点），自动匹配历史策略库，生成具体的、可执行的策略方案，包含目标人群、动作参数、预期效果。

### 策略本体模型

```turtle
:Strategy a owl:Class ;
    rdfs:label "业务策略" ;
    :hasAttribute [
        :triggerCondition "归因断点类型/指标阈值" ;
        :targetPopulation "适用人群" ;
        :actionTemplate "动作模板" ;
        :expectedOutcome "预期效果" ;
        :historicalPerformance "历史表现数据" ;
        :riskLevel "风险等级"
    ] .

# 示例：专项邮件补足策略
:MailSupplementStrategy a :Strategy ;
    :triggerCondition "mail_channel.step3_to_step4_rate < 0.7 AND is_send_zx=0" ;
    :applicableScenarios :MAIL_LEAKAGE, :NEW_POPULATION_LOW_PENETRATION ;
    :actionTemplate "对{target_population}补发{email_template}，发送时段{send_time}" ;
    :expectedOutcome "+8~12pp ③→④转化率提升" ;
    :historicalPerformance [
        :deployedIn "6.3下半" ;
        :actualLift "+10.2pp" ;
        :successRate "0.82"
    ] .
```

- **标准化**：同类问题给同类解决方案，避免因人而异

## 能力四：策略仿真推演

> **先预测，再执行**

### 核心定义
在策略实际执行前，基于历史同类策略的数据和当前业务状态，预测策略对各指标的影响，识别潜在风险，支持"沙盒式"策略评估。

### 仿真维度

| 维度 | 说明 | 输出 |
|-----|------|------|
| **效果预测** | 策略对核心指标的变化预测 | 渗透率/转化率/流水等指标的预测区间 |
| **多指标联动** | 策略的副作用分析 | 客单价下降、渠道冲突等风险识别 |
| **人群影响** | 不同人群的差异化反应 | 四类人群的各自收益预测 |
| **时机敏感** | 策略执行时机的影响差异 | 卡池热度、竞品动态等外部因素 |

### 仿真示例

```
输入：对纯新玩家发放10%优惠券，预期提升渗透率

历史模式匹配：6.3下半"新玩家优惠券"策略
    • 渗透率提升: +5.2pp
    • 转化率提升: +3.8pp  
    • 客单价下降: -8%
    • 自然转化替代: 15%

当前场景调整系数：
    • 卡组热度：6.4下半热度高15% → 效果×1.1
    • 人群基数：新玩家多20% → 绝对收益+20%
    • 渠道饱和度：邮件触点已达上限 → 边际效益-5%

┌─────────────────────────────────────────┐
│           仿真预测结果                   │
├──────────────────┬──────────┬──────────┤
│ 指标             │ 当前值   │ 预测值   │
├──────────────────┼──────────┼──────────┤
│ 有效渗透率       │ 35.0%    │ 40.5%    │
│ 网充转化率       │ 45.0%    │ 49.5%    │
│ 客单价           │ ¥648     │ ¥583     │
│ 网充总流水       │ 1000万   │ 1250万   │
│ 优惠成本         │ -        │ 80万     │
│ 净收益           │ -        │ +170万   │
└──────────────────┴──────────┴──────────┘

风险预警：
⚠️ 客单价下降8%超出可接受范围(>5%)

建议调整：
  改为"满648减50"而非直接10%折扣
  → 预计减少客单价冲击至-3%
  → 重新仿真...
```

### 业务价值
- **降低试错成本**：上线前知道可能效果，避免盲目投入
- **快速决策**：分钟级出预测结果，不需要等2周AB实验
- **策略优化**：仿真阶段识别问题，调整参数后再执行

## 能力五：策略执行与监控

> **从"建议"到"落地"**

### 核心定义
将策略方案自动转化为具体的系统执行指令，部署到相应渠道（邮件/社区/游戏内），并实时监控执行过程，自动识别异常并触发调优或熔断。

### 监控指标体系

| 阶段 | 监控指标 | 异常阈值 | 自动动作 |
|-----|---------|---------|---------|
| 部署阶段 | Task覆盖率 | <95% | 告警+重试 |
| 发送阶段 | 发送成功率 | <90% | 暂停+人工介入 |
| 触达阶段 | 开信率 | 低于基线3pp | 触发标题优化建议 |
| 转化阶段 | H5点击率 | 低于基线2pp | 标记创意疲劳 |
| 最终阶段 | 整体ROI | 低于预期50% | 自动熔断 |

### 业务价值
- **执行零成本**：策略确认后自动落地，无需运营手动配置
- **问题早发现**：监控中间指标，比最终流水下降早1-2天发现问题
- **损失可控**：自动熔断避免错误策略大面积扩散

## 实施建议

### 阶段一：基础建设（1-2周）
1. **选择试点业务**：建议从有明确文档、口径相对成熟的业务开始（如网充）
2. **文档梳理**：收集核心文档（业务规范、数据口径、历史分析报告）
3. **初版本体构建**：使用AOF工具从文档提取核心实体和关系

### 阶段二：能力验证（2-4周）
1. **自然语言查询**：验证"用户问→AI答→结果准确"的闭环
2. **专家打标闭环**：在实际使用中收集专家反馈，完善本体
3. **归因能力验证**：对比AI归因与人工归因的结论一致性

### 阶段三：策略闭环（4-8周）
1. **策略库建设**：将历史有效策略编码进本体
2. **仿真校准**：用历史策略数据校准仿真模型参数
3. **自动执行对接**：与邮件系统、社区运营系统对接，实现一键部署
