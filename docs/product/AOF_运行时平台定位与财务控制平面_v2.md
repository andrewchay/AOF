# AOF 运行时平台定位与财务控制平面 v2

> **状态**：当前产品定位真值源
>
> **决策**：AOF 的终局是受治理的企业运行时平台；“本体工厂”是资产构建与实施能力，不是终局产品定位。
> **首个可审计证明点**：财务控制平面。

## 1. 一句话定位

AOF 是 CEO 主导的 AI-Native 企业转型的受治理运行时平台：它把企业语义、政策、授权、行动和结果证据编织成可运行的控制平面，让 Agent 与组织在可追责边界内持续发现问题、提出行动、完成审批、驱动执行并验证价值。

财务是第一个证明点，不是产品终点。它具备正式账本、明确的金额和责任主体、频繁的例外处理，以及对审批与审计的刚性要求，适合验证平台是否真正改变组织的运行方式。

## 2. 不是什么

- 不是知识图谱、RAG、BI 看板或 CFO 问答工具；
- 不是仅将自然语言转换为 SQL 的生成器；
- 不是第二套 ERP 总账：ERP 保持法定记录，AOF 是其上方的控制与运营层；
- 不是绕过责任人自动执行高风险动作的 Agent。

Text-to-SQL、BI Copilot、检索和看板仍然有价值，但只作为受语义、权限、策略与证据约束的入口或消费面。

## 3. 财务控制平面闭环

```text
ERP / 预算 / 银行 / 采购 / 合同 / 运营数据
  → 财务语义图、版本化 Policy Pack、责任与权限
  → 异常、机会与风险识别
  → 解释、影响推演与行动包
  → 人或确定性策略审批
  → 写回或编排业务系统中的受控动作
  → 结果、证据、例外升级、回滚/对账
  → Impact Ledger 归因与下一轮策略/语义更新
```

平台的单位不是“一个回答”或“一条 SQL”，而是一个**受治理行动包**。每个行动包至少包含：

- `CapabilityManifest`：要运行的能力和语义版本；
- `ControlManifest`：权限、风险、审批、职责分离和执行边界；
- `EvidenceManifest`：输入事实、来源、解释和决策依据；
- `TestManifest`：回归、仿真、发布与安全验证；
- `CommercialManifest`：基线、归因、责任和可计量价值范围。

## 4. 价值与责任

价值不是预测的“节省了多少人力”，而是被证明的经营结果。Impact Ledger 对每项主张标记：

`hypothesis → validated → realised / not_attributable / reversed`

只有在基线、归因、责任人和价值上限明确时，才可以将结果计入已实现价值。

| 角色 | 平台责任 |
|---|---|
| CEO / Owner | 目标、跨部门取舍、价值捕获与责任授权 |
| CFO | 财务语义、政策、例外闭环、价值确认 |
| CIO / Risk | 身份、数据边界、连接器、审计与安全控制 |
| 业务 Owner | 行动执行、事实确认、结果回流 |
| Agent | 发现、解释、准备、编排；不越过高风险授权边界 |

## 5. 首个验证范围

首个财务闭环应选择一个高频、可度量、可追责的例外流程，例如现金预测偏差、应收催收例外、采购支出控制或预算偏差处置。范围必须包含：

1. 明确的正式系统和数据来源；
2. 一个可发布的财务语义与 Policy Pack；
3. 真实历史案例的回放与证据链；
4. 明确的审批、升级、执行或人工确认路径；
5. 对结果、归因和未归因结果的 Impact Ledger 记录。

验收不是 Agent 是否“回答得像专家”，而是例外是否更快闭环、控制是否未被绕过、结果是否可审计，以及价值是否可归因。

## 6. 商业路径

```text
Transformation Diagnostic
  → Transformation Program
  → Governed Operating Platform
  → Managed Transformation Office
```

“本体工厂”能力服务于诊断与实施阶段：构建语义资产、Policy Pack、回归样例和证据基础。平台许可与持续运营服务才承载长期价值。定价应按实体、流程、复杂度与治理责任设计；只有归因边界清晰时才考虑结果费用。

## 7. 当前实现与验证边界

仓库已具备 Semantic IR、release、治理、推理、仿真、动作计划/运行/补偿和决策溯源等机制。它们是财务控制平面的必要基础，但不是财务闭环已在客户生产环境验证的证据。

外部 ERP/银行/采购连接器、身份与密钥基础设施、容量/灾备、正式审批操作和真实价值归因，均须在具体客户环境中完成独立验收。
