# AOF 产品蓝图 v1（面向 AI-Native 转型）

最后更新：2026-04-01  
适用阶段：0-6 个月产品化推进

## 1. 产品定位

**AOF = 企业语义底座工厂（Semantic Layer Factory）**  
通过导入历史文档、规则、SQL、反馈，构建可被 AI Agent 直接调用的语义资产（本体、关系、mapping、回归规则），支撑企业从“文档驱动的人”向“语义驱动的 Agent 协作”转型。

### 1.1 一句话价值

让不同 Agent 在同一企业语义上工作，减少幻觉、口径漂移和跨团队认知断层。

### 1.2 核心产出物

1. 本体与关系图（OWL + 关系）
2. 业务 mapping 库（术语、指标、维度、SQL 模板）
3. 回归样例库（上线前门禁）
4. 语义构建清单（manifest + 版本信息）

## 2. 目标客户与适配场景

### 2.1 传统互联网 / 游戏公司

典型痛点：
- 指标口径分散，文档与 SQL 不一致
- 业务策略复盘难沉淀，换人即失忆
- Text-to-SQL 容易“看起来对，实际错”

高价值场景：
1. BI Copilot 与 Text-to-SQL
2. 投放/增长策略 Agent（ROI、LTV、净增口径）
3. 运营/客服知识问答
4. 研发 Agent 的业务规则约束生成

### 2.2 投资公司（一级/二级、研究机构）

典型痛点：
- 投研框架分散在报告、会议纪要、模型文档
- 因子定义和行业口径版本不一致
- 尽调问答依赖“老研究员经验”

高价值场景：
1. 投研术语库与行业知识图
2. 因子定义与回测口径标准化
3. 尽调 Copilot（有来源约束）
4. 组合复盘与策略偏差解释

### 2.3 传统制造业

典型痛点：
- 工艺/SOP/故障经验分散在 PDF/Excel/邮件
- 质检规则和现场执行口径不一致
- 设备问题排查高度依赖老师傅

高价值场景：
1. 工艺与质检规则语义化
2. 设备故障诊断知识图
3. 供应链异常归因问答
4. 生产报表语义查询（跨系统口径统一）

## 3. 功能分层（产品能力地图）

### L1 知识摄取层
- 多源导入：文档、SQL、元数据、反馈
- 批量/增量摄取
- 数据质量预检

### L2 语义构建层
- 本体抽取与关系构建
- 术语归一与歧义消解
- 实体属性与规则绑定

### L3 语义治理层
- mapping 库管理（术语/指标/维度/模板）
- 回归样例管理
- 语义版本化（manifest）

### L4 Agent 接入层
- 检索接口
- 解释接口
- 约束生成接口（尤其 Text-to-SQL）
- 结果校验与回归门禁

### L5 反馈进化层
- 线上错误回流
- 自动建议（skills/rules update suggestions）
- 人工确认后再发布

## 4. 版本与定价分层

> 按你的要求：多租户/权限作为付费版重点能力。

### 4.1 Base（基础版）

适合：单团队试点、POC、内部效率改造  
包含：
- 语义构建全流程（导入 -> 本体 -> mapping -> regression）
- 基础 API 与 CLI
- 本地/私有部署（单组织）
- 基础回归门禁

### 4.2 Pro（专业版）

适合：多部门协作、跨团队共用语义资产  
新增：
- 语义资产发布流水线（版本、diff、回滚）
- 增强可观测性（指标与告警）
- 行业模板包（游戏/投资/制造）
- Agent 接入 SDK 与集成支持

### 4.3 Enterprise（企业版）

适合：集团级治理与合规要求  
新增（付费核心）：
- 多租户与权限系统
- 审计日志与审批流
- 组织级策略与合规配置
- SLA、专属支持与驻场落地

## 5. 6 个月里程碑

### M1-M2：行业可落地 Starter Pack
- 交付 3 套模板：互联网/游戏、投资、制造
- 每套包含：术语模板、规则模板、回归模板、Demo 数据
- 目标：首次部署周期 <= 2 周

### M2-M3：Agent 接入标准化
- 发布统一调用协议：Retrieve -> Constrain -> Generate -> Validate
- 提供 Text-to-SQL 参考适配器
- 目标：接入新 Agent 时间 <= 3 天

### M3-M4：发布流水线产品化
- 语义资产版本化、差异比较、回滚机制
- CI 门禁：回归不通过不可发布
- 目标：语义变更可追踪率 100%

### M4-M6：商业化能力上线
- Pro 能力完善并形成标品
- Enterprise 上线多租户/权限/审计
- 目标：形成可复制交付方法论与报价包

## 6. 验收指标（北极星 + 分层指标）

### 6.1 北极星指标
- **Agent 业务任务一次正确率**（First-pass correctness）

### 6.2 产品指标
1. 语义构建效率  
- 从文档到可用 mapping 的周期（天）
2. 语义一致性  
- 同类问题跨 Agent 答案一致率
3. 回归稳定性  
- 版本发布回归通过率
4. 业务采纳度  
- 周活跃 Agent 调用量、覆盖团队数
5. 价值产出  
- 人工分析工时节省、错误决策率下降

### 6.3 行业示例 KPI
- 游戏：投放口径争议工单下降 >= 40%
- 投资：尽调问答准备时间下降 >= 30%
- 制造：故障定位平均时间下降 >= 25%

## 7. 当前还不满足的诉求（除权限后置外）

1. 行业模板仍需系统化（目前偏通用）
2. Agent 统一 SDK 还未成型
3. 语义资产版本治理体验需产品化
4. 可观测性与运营看板不足

## 8. GTM 与落地建议

1. 先从“一个高价值语义域”切入，而不是全公司一次性改造  
2. 先跑“可衡量闭环”：导入 -> 构建 -> Agent 使用 -> 回归 -> 反馈  
3. 每个行业优先打 2-3 个样板客户，沉淀可复用模板  
4. 把“正确率提升 + 时间节省”作为销售主叙事

## 9. 附：推荐试点包（首月）

1. 选一个主题域（如投放 ROI、行业因子库、质检异常）
2. 导入 50-200 份历史文档
3. 产出第一版 ontology + mapping + regression
4. 接入一个下游 Agent（优先 Text-to-SQL）
5. 连续 2 周通过反馈迭代至少 2 个版本
