## 系统分层

### 1. 接入层 (Access Layer)

负责处理所有外部请求，提供统一的安全和流量控制。

**组件：**
- **认证 (Auth)** - JWT Token / API Key 验证
- **限流 (Rate Limiter)** - 令牌桶 / 滑动窗口算法
- **审计 (Audit)** - 请求日志记录
- **租户解析 (Tenant Resolution)** - 从请求中提取租户信息

**关键类：**
- `AuthenticationMiddleware` - FastAPI 认证中间件
- `RateLimiter` - 限流器
- `AuditMiddleware` - 审计中间件
- `TenantMiddleware` - 租户识别中间件

### 2. 业务服务层 (Bridge Layer)

核心业务逻辑层，将上层请求转换为底层存储操作。

**模块：**

| 模块 | 职责 | 关键类 |
|------|------|--------|
| `ingest` | 数据摄取 | `BatchIngestor`, `IncrementalLoader` |
| `sync` | 数据同步 | `DataSync` |
| `analytics` | 图谱分析 | `GraphAnalytics` |
| `search` | 智能搜索 | `EnhancedSearch` |
| `visual` | 可视化 | `GraphVisualizer` |
| `tasks` | 异步任务 | `TaskQueue`, `GraphAnalyticsExecutor` |

### 3. 企业级能力层 (Enterprise Layer)

提供企业级功能支持，与业务逻辑解耦。

**子系统：**

#### 3.1 认证授权 (Auth)
```
┌─────────────────────────────────────────┐
│              RBAC Manager               │
├─────────────────────────────────────────┤
│  User ──► Role ──► Permission ──► Resource │
│                                          │
│  • 4 级角色 (admin/owner/editor/viewer)   │
│  • 资源级授权                             │
│  • NebulaGraph 用户同步                   │
└─────────────────────────────────────────┘
```

#### 3.2 多租户 (Tenant)
```
┌─────────────────────────────────────────┐
│           Tenant Manager                │
├─────────────────────────────────────────┤
│  Tenant ──► GraphSpace ──► Quota        │
│                                          │
│  • 租户隔离 (GraphSpace)                  │
│  • 资源配额管理                            │
│  • 租户生命周期 (active/suspended/deleted) │
└─────────────────────────────────────────┘
```

#### 3.3 缓存 (Cache)
```
┌─────────────────────────────────────────┐
│           Cache Manager                 │
├─────────────────────────────────────────┤
│  L1 (Local LRU) ──► L2 (Redis)          │
│                                          │
│  • 多级缓存                               │
│  • 物化视图 (Materialized View)           │
│  • 防击穿 (Thundering Herd Protection)    │
└─────────────────────────────────────────┘
```

#### 3.4 弹性 (Resilience)
```
┌─────────────────────────────────────────┐
│         Resilience Components           │
├─────────────────────────────────────────┤
│  RateLimiter │ CircuitBreaker │ Retry   │
│                                          │
│  • 令牌桶限流                              │
│  • 熔断器 (CLOSED/OPEN/HALF_OPEN)         │
│  • 指数退避重试                            │
└─────────────────────────────────────────┘
```

### 4. 存储抽象层 (Storage Layer)

提供统一的存储接口，支持多种后端。

**设计模式：**
- **抽象工厂** - `StorageFactory` 创建不同后端
- **策略模式** - `GraphBackend` 接口统一不同实现

**支持后端：**

| 后端 | 适用场景 | 特性 |
|------|----------|------|
| Cognee | 单机/原型 | 轻量、易部署、与 AOF 深度集成 |
| NebulaGraph | 生产/大规模 | 分布式、水平扩展、亿级节点 |

## 核心模块详解

### 存储层 (Storage)

```python
# 统一接口示例
class GraphBackend(ABC):
    @abstractmethod
    async def add_triples(self, triples: List[Triple]) -> int: ...
    
    @abstractmethod
    async def pagerank(self, top_k: int = 100) -> List[PageRankResult]: ...
    
    @abstractmethod
    async def community_detection(self, algorithm: str) -> List[Community]: ...
```

**扩展点：**
- 实现 `GraphBackend` 接口可添加新存储后端
- 通过 `StorageFactory.register()` 注册

### 任务队列 (Tasks)

```
┌─────────────────────────────────────────┐
│            Task Queue                   │
├─────────────────────────────────────────┤
│  Priority Queue ──► Worker Pool         │
│                                          │
│  1. 提交 (submit) ──► 优先级队列          │
│  2. 调度 (schedule) ──► 工作线程          │
│  3. 执行 (execute) ──► 执行器             │
│  4. 存储 (persist) ──► Redis/DB          │
└─────────────────────────────────────────┘
```

**特性：**
- 优先级队列（4 级优先级）
- 并发控制（信号量）
- 进度追踪（0-100%）
- 自动重试（可配置次数）

### 缓存系统 (Cache)

```
Query ──► L1 Cache ──► L2 Cache ──► Source
              │            │            │
              ▼            ▼            ▼
           命中返回     回填 L1      计算结果
                      返回结果      回填 L2/L1
```

**策略配置：**
```python
# 搜索缓存 - 短时效
SEARCH_CACHE = CacheConfig(l1_ttl=300, l2_ttl=1800)

# 分析缓存 - 中时效能
ANALYTICS_CACHE = CacheConfig(l1_ttl=600, l2_ttl=3600)

# 本体缓存 - 长时效
ONTOLOGY_CACHE = CacheConfig(l1_ttl=0, l2_ttl=86400)  # L1 永不过期
```

## 扩展机制

### 1. 添加新存储后端

```python
# 1. 实现接口
class MyBackend(GraphBackend):
    async def add_triples(self, triples): ...
    async def pagerank(self, top_k): ...

# 2. 注册
StorageFactory.register("mybackend", MyBackend)

# 3. 使用
config = StorageConfig(backend_type="mybackend")
backend = StorageFactory.create(config)
```

### 2. 添加新任务类型

```python
# 1. 定义执行器
async def my_executor(task: Task):
    # 实现逻辑
    return result

# 2. 注册
from bridge.tasks.executors import register_executor
register_executor("my_task", my_executor)

# 3. 提交任务
task = Task(task_type="my_task")
await queue.submit(task)
```

### 3. 自定义缓存策略

```python
# 定义新策略
MY_CACHE = CacheConfig(
    l1_enabled=True,
    l1_ttl=600,
    l2_enabled=True,
    l2_ttl=3600,
)

# 应用到管理器
cache = CacheManager(config=MY_CACHE)
```

## 技术选型

| 领域 | 技术 | 理由 |
|------|------|------|
| 后端框架 | FastAPI | 高性能、自动生成文档、类型安全 |
| 图数据库 | NebulaGraph | 分布式、高性能、类 Cypher 语法 |
| 缓存 | Redis | 成熟、支持持久化、集群 |
| 任务队列 | 自研 + Redis | 轻量、可控、无需额外依赖 |
| 部署 | Kubernetes | 云原生、自动扩缩容、高可用 |
| 监控 | Prometheus | 云原生标准、生态丰富 |
